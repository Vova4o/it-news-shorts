# ADR 0001: Clean Architecture без избыточной абстракции

- Статус: принято
- Дата: 2026-11-12
- Этап: TASK 001

## Контекст

Сервис должен собирать новости, генерировать видео и публиковать их без
участия человека. Внешних зависимостей много (LLM, TTS, video API, YouTube,
MinIO, Temporal, PostgreSQL), и каждая может измениться. При этом на первом
этапе запрещено подключать реальные интеграции.

## Решение

1. Один Go-модуль, `internal/*` для всего прикладного кода.
2. Домен (`internal/domain`) не импортирует ничего, кроме стандартной
   библиотеки: модели, инварианты, машина состояний, расписание.
3. Каждый внешний сервис описан минимальным интерфейсом в своём пакете
   (`news`, `ai`, `script`, `audio`, `video`, `youtube`, `storage`, `notify`).
4. Оркестрация вынесена в `internal/workflows` как контракт
   `DailyRunWorkflow` + структура `Steps`; конкретная реализация появится с
   Temporal.
5. Никаких репозиториев-обёрток над ещё не существующей БД и никакого
   `pkg/` с «общими утилитами».

## Последствия

- Домен тестируется без Docker, сети и системных часов.
- Замена провайдера не затрагивает домен.
- Небольшое дублирование проверок в типах запросов портов — принято осознанно:
  каждый контракт проверяет свои поля.
- Пакеты `migrations`, `configs`, `deployments` пока содержат только README:
  пустых Go-пакетов без необходимости нет.

## Альтернативы

- **Один пакет `app`.** Быстрее на старте, но машина состояний и порты
  смешались бы с инфраструктурой.
- **Полный DDD с агрегатами-репозиториями и событиями.** Избыточно для этапа,
  где нет БД и брокера.
